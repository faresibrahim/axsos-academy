Fix 1 — in Hero.collect()

Replace:

self.coins += amount

With:

self.backpack.add_coins(amount)

Why? Hero does not have a coins attribute. Its backpack does. Calling add_coins() also reuses the existing logic in the Backpack class instead of duplicating it.

Fix 2 — in Hero.gift_coins()

Add one line inside the existing if block:

self.backpack.spend_coins(amount)

The relevant method becomes:



def gift_coins(self, other_hero, amount):
    if self.backpack.coins >= amount:
        self.backpack.spend_coins(amount)

    return self

Without this second fix, the recipient receives coins, but the sender loses nothing. That's a game-logic bug rather than a compilation error.

4. What you should learn from this bug
The most important lesson is the difference between an object's own attributes and the attributes of another object it contains.

self.coins means the Hero object should have a coins attribute.

self.backpack.coins means access the coins attribute belonging to the Backpack object.

self.backpack.add_coins(amount) means ask the backpack to update its own balance through its method.

This design is called composition: a Hero has a Backpack. The backpack manages its own coin balance, so the hero should delegate coin operations to it.

One final distinction: Python does not fail to compile this code. It parses successfully, then raises an AttributeError when collect() tries to access the missing self.coins attribute. The gift deduction issue is a separate logical bug that would remain after fixing the runtime error.
