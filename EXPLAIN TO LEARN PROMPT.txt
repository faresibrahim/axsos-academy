Express Middleware Explained
1. What is Express middleware?
Middleware is a function that runs between receiving an HTTP request and sending a response.

In a full-stack application, the frontend sends requests to the backend. Before the backend sends a response, it often needs to perform tasks such as checking authentication, reading data from the request, or logging information.

Middleware helps us handle these tasks.

1. Frontend sends a request

GET /patients

2. Middleware runs

Check authentication, log request, etc.

3. Route handler runs

Fetch patients and prepare a response

4. Backend sends a response

JSON data returned to the frontend

Think of middleware as a checkpoint. A request passes through it before continuing to its destination.

2. What is middleware used for?
Common use cases include:

Authentication: Check whether a user is logged in.

Authorization: Check whether a user has permission to access a resource.

Logging: Record incoming requests for debugging.

Parsing data: Make JSON sent by the frontend available to the backend.

Error handling: Handle errors in a consistent way.

3. Your first middleware example
Here is a simple Express application:

const express = require("express");
const app = express();

// Middleware
app.use((req, res, next) => {
  console.log("A request was received!");

  next();
});

// Route
app.get("/", (req, res) => {
  res.send("Hello World!");
});

app.listen(3000);

Let's break it down.

req — Request

Contains information about the incoming request, such as its URL, headers, and data.

res — Response

Lets you send a response back to the client.

next() — Continue

Tells Express to move to the next middleware or route handler.

For example, when someone visits http://localhost:3000/, the console prints:

A request was received!
Then the route responds with:

Hello World!
Important: If middleware neither sends a response nor calls next(), the request can get stuck waiting.

4. Middleware in a real application
Imagine you're building PhysioLink, and you have an endpoint that returns patient information.

You don't want unauthorized users accessing it.

function checkAuth(req, res, next) {
  const isLoggedIn = false;

  if (!isLoggedIn) {
    return res.status(401).json({
      message: "Unauthorized"
    });
  }

  next();
}

app.get("/patients", checkAuth, (req, res) => {
  res.json(["Patient A", "Patient B"]);
});

Here's what happens:

The frontend requests /patients.

checkAuth runs first.

If the user isn't authenticated, Express returns a 401 Unauthorized response.

The route handler never runs.

If authentication succeeds, next() allows the request to continue.

This example uses a fixed Boolean for learning purposes. A real application would verify a session, token, or other authentication mechanism.

5. Built-in middleware
You don't have to write every middleware function yourself. Express provides useful built-in middleware.

For example:

app.use(express.json());

This middleware parses incoming JSON request bodies so you can access the data through req.body.

Suppose the frontend sends:

{
  "name": "Ahmad",
  "age": 25
}

Your backend can then read it:

app.post("/patients", (req, res) => {
  console.log(req.body.name); // Ahmad
  res.send("Patient received");
});

Without express.json(), Express won't automatically parse that JSON body for you.

6. The key concept to remember
Middleware doesn't replace routes. They have different jobs.

Middleware

Route handler

Performs shared or preliminary tasks

Handles a specific endpoint

Can inspect or modify the request

Processes the requested operation

Can stop the request or pass it onward

Usually sends the final response

A typical Express request follows this pattern:

Request → Middleware → Route handler → Response

There can be multiple middleware functions, and their order matters. Express executes them in the order they are registered, subject to how each function handles the request.
